# INC-102: Duplicate points from Kafka redelivery

**Date:** 2024-06-18
**Severity:** SEV-2
**Service:** Rewards / TransactionConsumer

## Summary
About 4,000 members received double points for transactions processed between
14:05 and 14:40 UTC.

## Root cause
A broker failover caused Kafka to redeliver messages on `transactions.v1`.
`TransactionConsumer` committed offsets after awarding points, but had no idempotency
check, so redelivered transactions were awarded twice.

## Resolution
Added an idempotency check: `TransactionConsumer` now skips any transaction ID already
present in `rewards_ledger`. Duplicate points were reversed by a one-off script.
